# Step 2.2.10 — CPU-only Docker image and GitHub Actions CI

> **Status: completed and validated.** The Docker image was built and smoke-tested
> locally, and all three GitHub Actions jobs passed (Windows tests, Linux
> tests, and Docker build + HTTP smoke test).

The Docker image is intended for **reproducible API startup without a model**.
It excludes PyTorch, Ultralytics, pretrained weights and test artifacts.
It is NOT a GPU inference image: setting MODEL_PATH to a `.pt` file
without installing the model dependencies will not enable YOLO.

## Dependency groups

- `requirements-runtime.txt`: API runtime packages only.
- `requirements.txt`: development/test dependencies, includes runtime file.
- `requirements-model.txt`: optional Ultralytics model packages, includes
  `requirements.txt`. For CUDA-enabled Windows PyTorch, continue using the
  separately selected compatible PyTorch installation.

## Pretrained weights and real YOLO inference

**The default Docker image is intentionally model-free.** The `weights/`
folder is excluded from Git and from the Docker build context. Even if
`MODEL_PATH` is set inside this image, it cannot run YOLO `.pt` inference
because PyTorch and Ultralytics are not installed there.

To test real inference **on the Windows host**, first install the optional
`requirements-model.txt`, prepare PyTorch for CPU/GPU as appropriate, and
then download the official YOLO11n weights into `weights/yolo11n.pt`:

```powershell
python -m pip install -r requirements-model.txt
New-Item -ItemType Directory -Force '.\weights' | Out-Null
python -c "from ultralytics import YOLO; YOLO('weights/yolo11n.pt')"
Test-Path '.\weights\yolo11n.pt'
$env:MODEL_PATH = (Resolve-Path '.\weights\yolo11n.pt').Path
$env:MODEL_DEVICE = 'cpu'   # use '0' only with a working CUDA PyTorch installation
$env:MODEL_POOL_WORKERS = '1'
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Then check `/ready` (expected HTTP 200) and send the provided
`test_data/ai_generated_car.jpg` to `/v1/detect`. See the
[main README's step-by-step model setup](README.md#quick-start-windows-python-312)
for the CUDA install command and sample HTTP request.

Weights may be governed by Ultralytics' AGPL-3.0 or commercial licensing;
do not assume that downloading or excluding them from Git removes these
obligations. Review the [official Ultralytics licensing information](https://www.ultralytics.com/license)
before distributing or deploying a model-enabled service.

## Local checks (Windows PowerShell)

From the repository root and active `cv-inference-api-env`:

```powershell
python -m pip install -r requirements.txt
python -m pytest -q

docker build -t cv-inference-api:cpu .
docker run --rm -d --name cv-api-local -p 127.0.0.1:8000:8000 -e MODEL_PATH= cv-inference-api:cpu
python scripts/smoke_http.py --base-url http://127.0.0.1:8000
docker logs cv-api-local
docker stop cv-api-local
```

If PowerShell blocks `Activate.ps1`, for the current terminal only:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\cv-inference-api-env\Scripts\Activate.ps1
```

**Expected:** `/health` -> 200; `/ready` -> 503 because no model is
configured; `/openapi.json` -> 200. This is not evidence of successful
real-model inference. Model-enabled testing is done on the host with the
model dependencies installed.

## CI

`.github/workflows/ci.yml` runs on pushes to `main`, pull requests and
manual dispatch. It runs the fake-detector/validation/test suite on Linux
and Windows using Python 3.12 and builds and smoke-tests the CPU-only
Docker image on Linux. No GPU, model weights, Ultralytics or secret tokens
are required. CI cannot prove CUDA performance or availability.

For Docker Desktop on Windows, enable Linux containers and ensure Docker
Engine is running. Changes to GitHub Actions only execute after the
workflow file has been pushed to a GitHub repository.
